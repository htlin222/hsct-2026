# 詳解格式規格 v2(每題一份 markdown)

目標讀者:準備「血液及骨髓移植專科醫師筆試」的血液科主治/總醫師。風格:**UpToDate 式、標題階層為主結構、短句**,不是散文。

## 結構原則(這一版最重要的改變)

- **先用標題分層(`#` → `##` → `###` → 必要時 `####`),標題不夠用才用清單。**
  - `#` 一個:這題的主題(一句,不要寫「第 N 題」)
  - `##` 六個固定區段(標題文字一字不差,順序固定)
  - `###` 每個區段底下的子題:一個考點 / 一個原理 / 一個面向 / 一個選項組 / 一句 take home / 一章
  - `###` 底下直接寫 1–3 句短句(一行一句,句與句之間空一行或接著寫都可以)
  - **只有在要列舉 3 個以上並列的短項目時**才用 `-` 清單(例如逐選項判斷、藥物清單),**最多一層巢狀**,絕不三層
- 每題長度 400–800 字(中文計),有表格可到 900
- 每句都要有資訊量,不寫「本題考的是…」「以下說明…」這種空話

## 六個區段的寫法

```
# <主題一句,例如:RIC 與 MAC 在 AML 移植的取捨>

## 1. Topic review:高頻考點
### <考點一,例如:強度定義(Bacigalupo 2009)>
MAC = 不可逆骨髓抑制、必須幹細胞支持;RIC = 深但可逆;NMA = 幾乎不抑制。
### <考點二,例如:BMT CTN 0901 的數字>
復發 **48% vs 14%**、TRM **4% vs 16%**、OS 無差。
### <考點三 …>(3–6 個)

## 2. 第一性原理
### <原理一,例如:RIC 的治療效果來自 GVL,不是化療>
為什麼:… (1–3 句,講底層機轉/生物學/統計邏輯)
### <原理二 …>(2–4 個)

## 3. MECE 框架
### <軸的名稱,例如:依強度 × 目的拆解>
(適合比較的放表格;欄是面向、列是選項,格子裡是短句或數字)
| 面向 | MAC | RIC |
| --- | --- | --- |
| 目的 | 清除腫瘤 | 免疫抑制 + GVL |
### <另一軸 …>(1–3 個軸)

## 4. 解題思路
### 關鍵線索
一到兩句:題幹哪個字決定了方向(反向題?年齡?MRD?)。
### 逐選項
- (A) ✗ 一句理由
- (B) ✓ 一句理由
(K-type 題:逐條 (1)–(4) 判斷,再寫「→ 組合 = X」)
### 正解:**X**
一句話說為什麼只有它成立。有爭議時加一段「⚠️ 爭議點:…」。

## 5. Take home
### <一句能背的話,含數字門檻>
### <第二句>
(2–4 個 ###,每個底下可以空白或補一句)

## 6. 相關 EBMT Handbook 章節
### Ch<N> <章名>,PDF p<起>–<迄>
這一章跟本題相關的小節 / 關鍵句(一行)。
### Ch<M> …(1–3 章;**頁碼要真的 grep 到**,沒把握就只寫章名)
```

## 表格
- GitHub pipe table,一定要有表頭與分隔列;每題 0–2 張,**只在真的是比較/分類時用**
- 格子裡不要換行、不要用 `|`

## 寫作規則
- 繁體中文;專有名詞、藥名、縮寫保留英文(GVHD、PTCy、tacrolimus),少見縮寫第一次出現括號展開
- 短句,數字門檻要精確(劑量、天數、百分比、分級切點)
- **粗體**只用在:關鍵數字、正解字母、Take home 的門檻
- 引用集中在第 6 段,其他段不要塞「根據 EBMT 第 X 章」
- 不確定就寫「文獻不一致」或「手冊未涵蓋」,不要編數字
- 不要重抄題幹與選項全文;逐選項用「(A) ✗ …」帶關鍵詞即可
- 不要用 `>` 引用區塊(系統會另外在 114 年加警語),不要用 HTML
